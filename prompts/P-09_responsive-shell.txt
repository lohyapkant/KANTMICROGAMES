# TASK — KANT MICRO build 008: make the shared shell responsive, input-aware and safe on phones, tablets, foldables and desktops

## 0. WHAT YOU ARE EDITING, AND THE BOUNDARIES
`index.html` is a single-file, fully offline, MIT-licensed HTML5 project (~3,950 lines, vanilla JS + Canvas, no dependencies): a shelf screen plus four pixel-art micro games — PANDASNACK, BOOPEEK, DUCKLINE, SPROUTUP. Each game is a sealed IIFE that registers itself in `GAMES` and talks to the app only through the module contract: start / stop / restart / update(dt) / paint(ctx) / onDir(dir, pressed) / onAction() / onStageTap() / onAnyKey(), plus name, tagline, concept, actionLabel, hint, versionNumber, previewPaint.

That contract already IS the project's input-action layer. The games never touch the keyboard, pointer, DOM, audio or timers (verified by search: no listeners, timers, audio or window/document use inside the four IIFEs). So do NOT build a new input system and do NOT rewrite any game. All work happens in the shared shell: the <style> block, the HTML body, PART 3 (shelf), PART 4 (runtime), PART 6 (boot), and docs.

Rules (from the file's own READ ME FIRST block and the owner's standing requests):
1. PANDASNACK, BOOPEEK and DUCKLINE are FROZEN: make zero edits inside their IIFEs. Leave SPROUTUP alone too; it needs no change. If you believe something can only be fixed inside a game module, STOP: report the line numbers and the reason, and do not edit.
2. Keep the module contract exactly as is. Do not add required members; any optional runtime feature must be guarded with typeof checks.
3. Do not change gameplay, balance, art, or text drawn inside the canvases. Do not change STAGE_SIZE or the stage canvas backing size (100x100): the games paint in that coordinate space. All scaling happens in CSS.
4. Stay one offline file: no network calls, no web fonts, no libraries, no build step. Keep the MIT header and the shelf footer's license text and both links.
5. Keep saved data intact: best scores live at `KANTMICROGAME.<GAMEID>.best`. New settings use the same prefix with a non-colliding name (e.g. `KANTMICROGAME.ui.controls`) and the same try/catch pattern as readBest/saveBest.

## 1. OWNER DECISIONS (these defaults apply unless the owner edited them before pasting)
D1 Zoom — ALLOW page zoom. Remove `maximum-scale=1.0, user-scalable=no` from the viewport meta (it blocks zoom on Android and desktop browsers, iOS ignores it anyway, and it fails WCAG 1.4.4). Prevent accidental double-tap zoom with `touch-action: manipulation` on chrome and `touch-action: none` on the stage and pads instead. (If the owner changes this to KEEP LOCKED, leave the meta alone.)
D2 Pads on keyboard/mouse devices — AUTO. Show the on-screen pads while touch is the active input; collapse them when the active input is keyboard/mouse on a device with no touch support; follow the most recent input on hybrid devices. Add a tiny manual override (Auto / Always show / Always hide) and a "pads on left / right" mirror option for left-handed play, both persisted.
D3 Scale fallback — keep whole-number stage scaling (2x or more) whenever header, stage and controls fit without page scroll. Only below that threshold may you use a non-integer CSS scale (still pixelated) so the page never has to scroll during play. Document the threshold in a comment.

## 2. BASELINE FINDINGS (build 007-20261101, headless Chromium with touch emulation)

BLOCKERS

F2 [measured] `buildCard` opens the game on `pointerdown`. A touch scroll that starts on a card launches the game (390x844: dragging up from a card opened BOOPEEK). [code] Right and middle mouse buttons open games too.
F3 [measured] Cards, ⌂ SHELF, RESTART and the pads listen to pointer events only; there is no click path. Tab then Enter, and Tab then Space, on a card do nothing, so keyboard-only and assistive-tech users cannot start a game.
F4 [measured] The game screen is taller than the viewport on most phones, so the page scrolls during play. ## 3. REQUIRED WORK (in this order; one reviewable step each)
STEP 1 — Shelf (F1, F2, F3, part of F13)
- Fix the shelf width so there is never horizontal overflow from 280 px to 3440 px; let the banner and chips wrap; explicitly center the game screen.
- Open games from a `click` handler on the card, so mouse, tap, keyboard Enter/Space and screen readers all work and a scroll gesture can never activate it. Make `openGame` idempotent. Give cards `touch-action: manipulation` and visible `:focus-visible` rings, and wrap `.card:hover` in `@media (hover:hover)`.
- GHOST-CLICK HAZARD: once cards react to click, the tap that closes a game must not leak a click onto a card that appears under the finger. Move ⌂ SHELF and RESTART to `click` too (keep pointer events only for hold-type controls: the pads and the stage). Test it by tapping ⌂ SHELF at a spot where a card will appear underneath.
- Tab order: ⌂ SHELF then RESTART. The pads are pointer-driven duplicates of WASD, so set tabindex="-1" on them and note this in CONTROLS.md.

STEP 2 — Game screen layout (F4, F5, F9, F10, F11)
- Make the game screen a no-scroll app shell: height from `100vh` with a `100dvh` override, `overscroll-behavior: none`, no page scroll while a game is open, `touch-action: none` on the stage and pads. The footer stays on the shelf only.
- Replace `fitStage()`'s magic numbers by measuring the real box left for the stage after header and controls are laid out (ResizeObserver on the arena, plus window resize, orientationchange and `visualViewport` resize, coalesced with rAF). Choose the largest whole-number scale (2-6) that fits; apply D3 below the threshold.
- Pick portrait vs landscape layout from the available aspect ratio (width >= height), not from `min-width:680px`. For near-square screens (foldable inner displays), choose whichever gives the larger stage.
- Compact header: ⌂ SHELF, title, SCORE and BEST in one slim row; hide the tagline on short screens.
- Landscape touch: direction cluster in the lower-left thumb zone, action button in the lower-right, stage in the middle (mirrored by the D2 option). Portrait: one controls row under the stage. You may split the plus-shaped pad into a direction cluster plus a separate action button if reach improves. Keep the existing look (colors, shadows, labels, press animation).
- Targets: every tappable control >= 48x48 CSS px (pads may be 58, shrinking to 48 on short screens), >= 8 px between targets, ⌂ SHELF and RESTART raised to >= 48 px. Controls never overlap the stage or each other.
- Safe areas: define `--sai-t/-r/-b/-l` as the four env(safe-area-inset-*, 0px) values and use only those variables everywhere, with 16-24 px extra clearance for controls near screen edges (OS edge gestures). This also lets tests simulate a notch by overriding the variables.
- Rotation, fold/unfold, split-screen and window resize are live resizes: re-fit WITHOUT calling start/restart on the module, without losing run state, and without leaving a pad pressed or mispositioned.

STEP 3 — Input-mode awareness (F6, D2)
- Detect the ACTIVE input from actual use, never from user-agent or "is mobile" checks: a touch or pen pointerdown means "touch"; a keydown or a mouse pointerdown/move (use event.pointerType) means "keys/mouse". `matchMedia('(pointer: coarse)')`, `(hover: none)` and `navigator.maxTouchPoints` are only the initial guess. Expose the mode as `data-input="touch|keys"` on <body> and switch live.
- Do not edit the frozen `hint` strings. In keys mode show `module.hint` (strip the leading "desktop: " for display only); in touch mode show a runtime-built hint from `module.actionLabel`, e.g. "pad to move · {ACTIONLABEL} or tap the stage · ⌂ to leave". The shelf chips switch the same way. Never show keyboard hints in touch mode or the reverse.
- Pad visibility follows D2; when the pads collapse, the stage may grow.

STEP 4 — Keyboard hygiene (F7)
- Ignore any key event with Ctrl, Meta or Alt held, so browser and OS shortcuts (Ctrl+R, Ctrl+S, Cmd+D, Alt+Left) pass through untouched and never reach the game. Do not preventDefault on them.
- Modifier keys alone, Tab, CapsLock and F1-F12 must not count as "any key". Keep Esc = shelf, R = restart, Space = action, WASD/arrows = move; Enter and other printable keys keep working as onAnyKey.
- Never hijack keys while an input, textarea, select or contenteditable has focus (none exist today; keep it future-proof).

STEP 5 — Lifecycle (F8)
- On `visibilitychange` (hidden), `pagehide` and `blur`: release every direction, clear pad visuals, and auto-pause. Pause is a runtime state: stop calling update/paint (the last frame stays on the canvas), show a small HTML overlay "PAUSED - tap or press a key" over the stage, and reset FRAME.lastTime on resume. The input that resumes must be swallowed so it does not also dash or poke. Esc still leaves to the shelf.
- Opening a game, leaving it, or a pointercancel must never leave a direction held (keep and extend releaseAllDirs).

STEP 6 — Pads (F12)
- Make the direction cluster one touch surface: a finger sliding from one direction to another switches direction; lifting or pointercancel releases it. Track every finger by pointerId so a second finger on the action button is unaffected. Hold + tap multi-touch must keep working.

STEP 7 — Polish (rest of F13)
- Visible focus styles everywhere; `#msg` as role="status" aria-live="polite"; chrome font sizes in rem; press and pulse animations respect prefers-reduced-motion; add a `100vh` fallback before each `100dvh`.
