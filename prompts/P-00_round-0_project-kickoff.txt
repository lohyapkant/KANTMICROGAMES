PROMPT ID: P-00 ROUND: 0 NAME: project-kickoff GAME NAME: KANTMICROGAME

PART 1. PROJECT MISSION (the owner's brief, kept in their own words)

"For this project, my plan is to get this project to generate HTML5 only 'micro games'.
The intention is to create super small games with simple concepts and small interfaces
that is cute, adorable, and also playable for a short while. My long term goal is to
include these microgames as part of a main game. So let us plan and see how it goes."

PART 2. THE OWNER'S CHOICES (answers from the planning questions, 2026-10-31)

1. Where the project lives: do not touch any of the other folders in the workspace.
   The project lives only in the existing empty folder KANTMICROGAME and generates
   HTML5 single-file games there.
2. Games are ALWAYS pixel art, shown in a small interface, about 100 by 100 pixels in
   size, scaled up on the screen with crisp pixels.
3. Controls: keyboard WASD on desktop; on mobile, on-screen (virtual) controls beside
   the small stage. The interface itself stays small; controls live around it.
4. A selection page is needed so the player can pick a micro game.
5. Supporting the future main game: keep it simple now. The micro games stay standalone.
   Real embedding support is deliberately NOT built in early rounds.
6. Round 0 is scaffold only: build the project frame, not a game yet.

PART 3. ROUND 0 BUILD TASK

Build the project scaffold only:
(a) a single-file offline selection page (the arcade shelf) with an empty card area,
    one dashed COMING SOON slot, a cute pixel-art mascot drawn in code, how-to-play
    notes for WASD, Space and touch pads, and a version footer;
(b) the README describing the project honestly as round 0;
(c) the CHANGELOG following the house format;
(d) the project plan saved in plans/micro-games.md;
(e) this prompt copy saved in prompts/.
No game exists yet. The first game, PANDASNACK, is the Round 1 task, chosen by the
owner when asked which game to build first.

PART 4. NOTES ON HOW THE DECISIONS WERE MADE

* Asked whether the owner wanted a curated collection, a true generator, or both:
  the answer landed on generating small single-file games in this folder, one at a
  time, each with its own tiny copied helper code so every file stays self-contained.
* Asked about art direction: pixel art, always.
* Asked whether games should be built embeddable from day one: "No, keep it simple",
  so no iframe, postMessage or engine dependency exists in this round.
* The plan document (plans/micro-games.md) records the seven micro-game rules, the
  stage spec, the control spec, the per-game settings recipe, the definition of done
  for game rounds, the round table and a backlog of eight possible games so the next
  rounds can start immediately.
